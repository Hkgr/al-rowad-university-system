# رواتب مالك الجامعة

تستخدم بوابة المالك ومكتب المحاسبة الإداري تنفيذًا شهريًا واحدًا، مع حارسين مستقلين. موظفو الرواتب هم العاملون الحقيقيون من `employees`، لا هويات مالية ينشئها مستخدم المحاسبة. صفحة الرواتب تبدأ باختيار الشهر، ثم العاملين والمدخلات والمستحق المحسوب والصرف الفعلي والاستلام الموثق.

## الحساب والبيانات

`PayrollConfigService` و`PayrollInput` و`PayrollCalculator` تظل المصادر الوحيدة لتعريف البنود والتحقق والمعادلات والتقريب. لم تُضف صيغة راتب أو نظام ضرائب أو تحويلات. العملة SYP والفراغ ليس صفرًا. يحفظ الشهر نسخة الأعمدة والإعدادات والمدخلات والخلايا؛ تغيير القالب للفترة التالية لا يعيد حساب شهر محفوظ. التصحيح المعتمد صريح ومؤرخ وله نسخة سابقة ثابتة.

المبالغ تعدّل في المحاسبة فقط. بيانات الهوية والعلاقة والدوام تأتي من HR وتعرض كمصدر قراءة؛ لا نموذج إنشاء موظف أو تعديل هويته أو ربط يدوي. السجل المالي لا يحذف بإيقاف العامل. الاستبدال الوحيد للبيانات التجريبية أمر صيانة مستقل بتأكيد ونسخة احتياطية ومراجعة جديدة تحت الأقفال.

## الوصول والواجهة

حارس المالك الحالي لا يتغير: مدير مركزي نشط وفق bypass القائم، أو دور مالك فعلي مع منح دوره الفعالة للدخول والإجراء. إعطاء نائب صلاحية مالية لا يمنحه بوابة المالك؛ يستخدم مدخل المحاسبة الإداري بالدور والصلاحية المعينة ونطاق جامعة حقيقي. التهيئة لا تنشئ حسابًا أو كلمة مرور أو نطاقًا.

`owner_payroll.view` للقراءة، `amounts.edit` للمدخلات، `periods.manage` لإعداد الشهر واعتماد مستحقه، `periods.correct` لتصحيحه بعد الاعتماد، `payments.manage` للصرف والاستلام وإلغاء الخطأ، `export` للتصدير، و`config.manage` للأعمدة والمعادلات والإعدادات. تسبق كل suffix هنا بادئة `owner_payroll.`. صلاحية هوية الرواتب القديمة لا تفتح إجراء إنشاء/تعديل مستقل.

الرئيسية تعرض فترة محاسبية محفوظة بعنوانها، مع انتقالات تطابق نطاق الأعداد. غياب الفترة أو القراءة المناسبة يظهر غير متاح، لا مبلغًا تقديريًا أو صفرًا مصطنعًا. ملفات العامل المحاسبية لها روابط مباشرة في بوابتي المالك والإداري. المرشحات والتقارير مرقمة بالخادم، والإجماليات للاختيار الكامل لا الصفحة وحدها. التقارير للقراءة والتصدير دون أزرار موافقة في تبويب التقارير.

## التشغيل والتصدير

[الدليل الكامل للموارد البشرية والمحاسبة الشهرية](hr-payroll-monthly-accounting.md) يبين migration الجديدة، الأوامر الدقيقة للصلاحيات، معاينة/تنفيذ استبدال التجربة، المزامنة العادية، إعداد خطوط PDF وقيود التحقق. لا تشغّل استبدال التجربة من migration أو GET أو مزامنة يومية.

PDF المحاسبي منفصل عن ملف HR: فترة وهوية وبنود ومعادلات ومجاميع وصرف واستلام ومراجع وتصحيحات، بالشعار وCairo وRTL وترويسات وترقيم. Excel يحتفظ بالقيم الدقيقة وتعريفات البنود والإجماليات والدفعات، لا معادلات محلية تعيد احتساب تقرير قديم. لا ختم أو توقيع أو إثبات تحويل مصنوع.

للتوثيق التاريخي فقط: [دليل الورقة السابقة عند PR161](https://github.com/Hkgr/al-rowad-university-system/blob/c5d4e2b50a7bbb145a0c65ac19e7b6d3aea9b86d/docs/owner-payroll.md). إنشاء الهوية المالية المستقلة والورقة غير المؤرخة والربط القديم انتهت في الواجهة الحالية، وليست بدائل للتشغيل الشهري. المكتبات والقفل والمعادلات الأصلية محفوظة. لا اختبارات مضافة أو مشغلة في هذه الجولة؛ نتائج PR156/160 التاريخية ليست دليل قبول للمرحلة الشهرية.
