# الشؤون الإدارية — تنظيم الواجهة

الأقسام الأولى أدناه توثق تنفيذ تنظيم الواجهة السابق. إصلاح صلاحيات مسؤول المديريات ومسارات المكاتب مذكور في قسم «صلاحيات النائب الموحدة» في نهاية الملف؛ لا تُعد اللقطات أو الفحوص القديمة تحققًا من هذا الإصلاح.

## النطاق والتصميم

تغيير Frontend فقط من `develop` عند `411b09866178751866b7c6052ae3a0d946437415` على فرع `codex/administrative-portal-organization-ui`.

اعتمد المستخدم [مسودة Superdesign، الإصدار 6](https://p.superdesign.dev/draft/c470a6db-9a10-42f5-90a1-8711cb6d02d6) قبل التنفيذ. المرجع البصري والكود الحاليان:

الإطار والشعار وCairo والألوان والحقول والمؤشرات والمخططات الحالية معاد استخدامها. لا مكتبة جديدة ولا تحميل خط خارجي. اعتماد اتجاه التصميم لا يُعد تحققًا بصريًا من التطبيق.

## الشكل الجديد

- الاسم المرئي للبوابة «الشؤون الإدارية»، مع بقاء المسمى الوظيفي «نائب رئيس الجامعة للشؤون الإدارية» والرمز التنظيمي `7`.
- الترتيب الأعلى: الرئيسية، مديرية الشؤون الإدارية `71`، مديرية الشؤون المالية `72`، مديرية شؤون الطلاب `73`، التقارير، طريقة الاستخدام.
- المديريات مجموعات قابلة للطي؛ المكاتب عناوين داخلها؛ الخدمات الفعلية روابط إلى المسارات الموجودة فقط. يفتح مسار التفاصيل مجموعته تلقائيًا عند الانتقال والتحديث والعودة.
- رموز الوحدات شارات صغيرة معنونة «رمز»، باتجاه LTR، وليست قيم المؤشرات.
- الرئيسية تعرض ثلاث بطاقات، تضم كل الأسماء والرموز المطلوبة. الوحدات بلا خدمات مخولة تظهر «لا توجد خدمات متاحة حاليًا» بلا روابط أو صفحات وهمية.
- البطاقات عمودية على الهاتف و768px، وفي ثلاثة أعمدة عند 1440px. يستمر درج الإطار الحالي عند عرض 820px فأقل. الأسماء الطويلة تلتف؛ مجموعات الطي أزرار أصلية ذات `aria-expanded` و`aria-controls` وتركيز واضح.
- التعديلات على الإطار مشروطة بالمكوّن الاختياري `Navigation` وclass خاصة بهذه البوابة. البوابات الأخرى تحتفظ بالتنقل المسطح. احترام reduced-motion محصور داخل `.administrative-portal`.

### المصدر المركزي والحدود

`App\Support\AdministrativeOfficeAccess` هو allowlist المكاتب والصلاحيات وأدوار التشغيل التابعة، ويُستخدم في التسجيل وحراس الخدمات والهوية. يمنح أمر التهيئة دور `vice_president_administrative` القائم كامل المجموعة المعروفة من `permissions/role_permissions`، وليس صلاحيات ظاهرية من العميل. لا prefix wildcard ولا قائمة «كل صلاحيات النظام». موظفو HR والمحاسبة وبقية المكاتب لا تُضاف إليهم حقوق جديدة تلقائيًا.

المسؤول العادي يلزمه حساب نشط وإسناد دور فعّال بدأ بالفعل وPRES university scope فعلي ونشط. صلاحيات دور النائب لا تدخل effectivePermissions عند غياب هذا النطاق أو أهلية الدور؛ مساهمات أدواره الأخرى تبقى كما كانت. لا تغيير لسلطة super_admin المركزية. لا تُضاف هوية employee/student أو أدوار موظفي المكاتب إلى المستخدم. مداخل staff المصرحة لا تفترض وجود employee_id للنائب، لكنها تعيد التحقق من الجامعة والعنصر، وتبقى الموارد غير المعروفة مغلقة. قوائم موظفي ومناصب المكتب وكاتالوجاته لها allowlist نطاق صريح، وليست تجاوزًا عامًا لجميع الجداول.

الهوية بعد الدخول ترجع الأدوار الفعلية فقط، والصلاحيات المسندة الفعلية، و`administrative_offices` لعرض سلطة تشغيل المكاتب؛ حارس React يقرأ هذا العقد ويظل يتحقق من كل صلاحية. الخادم يحسب الأهلية بنفسه ولا يثق بهذا الحقل الوارد من العميل. تعديل `HrOffice` ومواضع الدور الصارم في البريد والإدخال اليدوي والتقارير مكمل لهذا المصدر، دون bypass boolean أو استثناء لكل إجراء.

لا يُمنح `owner_portal.access` أو `owner_portal.home.view` أو إدارة موظفي الرواتب المستقلين أو الربط اليدوي التاريخي. لا `users_permissions.manage` أو `system_settings.manage` أو صلاحيات الرئيس/الوزارة/النائب العلمي، ولا قرارات العميد أو الموافقة الشخصية للمرشد أو استحقاق الأستاذ في طروحاته. كل المراجعات المالية وأسباب التصحيح والاعتمادات والأقفال وUUID واسترجاع نتائج الكتابة غير المؤكدة والتدقيق والتاريخ باقية. فحوص جاهزية مخطط التكميلي تسمح فقط بمنح المشرف الجديدة إضافة إلى المصفوفة القديمة المطلوبة، وترفض أي إسنادات غير مصرح بها؛ لا تعطيل لجاهزية المخطط.

### الوصول المحلي والتوافق

نفس `DashboardLayout` و`AdministrativeNavigation` والمكونات وCairo والجداول والحوارات والألوان تستخدم في كل مسارات المكاتب. `administrativeOfficePaths` ومكوّن OfficeLink يحافظان على البحث والفلاتر ومعاملات الوجهة ويحوّلان انتقالات الصفحات المعاد استخدامها إلى البوابة الإدارية فقط عندما تُعرض فيها؛ المسارات القديمة والتجربة العادية لموظفي المكاتب باقية. مكاتب غير منفذة تبقى غير متاحة. حقول الحسابات والرواتب والطلاب لا تتغير بسبب هذه الطبقة. الصفحات القديمة المعاد استخدامها التي كانت تثبّت عنوان الإنتاج صارت تقرأ `API_BASE_URL` الحالي، حتى تتفق الهوية وواجهات المكتب مع `VITE_API_BASE_URL` الخاص ببيئة التشغيل، دون تغيير بروتوكول الطلبات أو البيانات.

### أمر التفعيل الموحد — تعليمات غير منفذة

بعد نشر Backend المتوافق والواجهة المبنية كاملة، يستخدم المشغل المصرح الأمر التالي على البيئة المقصودة بعد مراجعة النسخة الاحتياطية والصلاحيات:

```sh
php artisan administrative-offices:provision-access --check
php artisan administrative-offices:provision-access
php artisan administrative-offices:provision-access --check
php artisan optimize:clear
```

`--check` قراءة فقط ويعرض كل صلاحية: READY أو MISSING_PERMISSION أو MISSING_ROLE_GRANT أو INCOMPATIBLE، ويعيد exit code غير صفري عند النقص. التطبيق ذري ومتكرر بأمان، ويسند المجموعة كاملة للدور الموجود فقط دون حذف منح قائمة أو إنشاء حساب/دور/نطاق/وحدة/بيانات عمل. يمكن تسجيل الرموز المفقودة المعروفة من آليات HR/المالك/البريد/الحسابات الحالية؛ غياب متطلبات الميزات الأساسية أو تعطيل/تعارض permission/module يمنع العملية كاملة ويوضح النقص بدل اختلاق إعدادات. لا تضف رايات مالية متفرقة.

أي راية تاريخية `hr-office:provision-access --grant-vp-*` أو `--grant-vp` تظل مقبولة، لكنها تفوض إلى الأمر الموحد الكامل؛ `--grant-hr` يحتفظ بمنحه القديمة المحدودة. هذا ليس منحًا تلقائيًا لموظفي HR أو المالية. لم تُنفّذ هذه الأوامر، حتى --check، على قاعدة بيانات في هذه الجولة. يلزم خروج الحساب القائم ثم دخوله مجددًا لتحديث هوية React؛ التحقق الخادمي يقرأ الصلاحيات والنطاق الفعليين في كل طلب. لا تغيير مخطط أو migration أو SQL مطلوب لهذا الإصلاح، ولا seeder شامل.

### حدود التنفيذ

`scientificOrganization.js` تصنيف عرض مستقل؛ الرموز ليست معرّفات قاعدة بيانات أو أعدادًا أو صلاحيات. `ScientificHome` يعرض شجرة 8 ثم 81/82 ثم الأقسام، بالرموز وخطوط الربط، ويستخدم عناصر nav الأصلية بعد `canAccess` بدل إنشاء سياسة وصول جديدة. `ScientificNavigation` يستهلك القائمة المفلترة أصلًا من DashboardLayout، ويفتح إدارة المسار النشط ويختار أطول مسار مطابق لتفاصيل الطلبات والحد الأدنى. مفاتيح إعادة التهيئة تخص مجموعات الإفصاح في القائمة فقط، لا صفحات الإدارة أو محرراتها أو مسوداتها.

الشجرة تصبح عمودية تحت 1024px، بخطوط ربط منطقية و`minmax(0, 1fr)` ونصوص قابلة للالتفاف. زر المجموعة الحقيقي يحافظ على `aria-expanded/aria-controls` والتركيز، ويعيد توسيع القائمة المختصرة عند طلب فتحها؛ الرموز تبقى ظاهرة. درج الهاتف وإغلاقه والتنقل العام تبقى مسؤولية DashboardLayout الحالي. CSS الجديد محصور بـ`.scientific-portal`.

بعد الهيكل تبقى عبارة النطاق الأصلية و`ExecutiveOverview` بنفس شرط الوصول ومصادر API وحسابات المؤشرات، ثم تفاصيل الهوية والنطاق الأصلية. أُزيل تكرار اختصارات الخدمات المنفذة خارج الهيكل والرسالة القديمة عن قسم غير منفذ؛ لم يُفتح سير عمل أو مسار جديد. لم تُنقل أرقام المسودة الاصطناعية أو scripts/fonts/CDN الخاصة بمعاينة التصميم إلى التطبيق.

الفرق في `App.jsx` يقتصر على استيراد ScientificNavigation واختياره مع اسم البوابة وclass معزولة للغلاف العلمي. بقيت جميع Route paths وعناصر الصفحات وProtectedRoute policies كما هي، وبقيت شروط كل عنصر nav كما كانت. فرع AdministrativeHome في VicePresidentShell وتفاصيل هويته لم يتغيرا.
